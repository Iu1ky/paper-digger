# Portable delegation and fallback matrix

Paper Digger must inspect the current host before dispatching. Product names and
skill names change; treat the capability as the contract and the examples only
as discovery hints.

| Need | Prefer when available | Built-in fallback |
|---|---|---|
| Literature discovery | deep-research, academic search, paper-spine research, scholarly connectors | Host web/search tools; query primary sources, save URLs/DOIs and retrieval dates |
| Full-text reading | paper/PDF reader or downloader | Open lawful OA/publisher copies; record inaccessible sources as blockers |
| Planning | Paper Digger plan skill plus domain planning skill | Falsifiable hypotheses, experiment matrix, one cheapest decisive probe |
| Figures/data | scientific figure/data skill | Generate from verified data with reproducible scripts and provenance |
| Academic drafting | academic-paper, paper-spine build, venue-specific writer | Draft section-by-section from the evidence bank and official template |
| Polishing | claim-preserving academic polishing skill | Edit for clarity while checking every changed claim against evidence |
| Review | academic-paper reviewer | Run one overall triage, then only the lenses needed for flagged dimensions |
| Revision | revision/rewrite skill | Maintain issue → evidence → action → verification table |
| Final formatting | LaTeX/compiler, format converter, disclosure helper | Follow the official author checklist line-by-line and log unresolved items |

## Host capability rules

1. Probe only the capability required by the current phase. Select one primary
   route; do not enumerate or load the host's complete skill/tool catalog.
2. Never claim a named skill was used if it was unavailable.
3. If the effort budget permits subagents or agent teams, delegate only
   independent work with explicit inputs and expected output schemas.
4. If it does not, execute the same lenses sequentially and preserve their
   independence by restating the evidence and adversarial role each time.
5. External API keys, MCP servers, SSH, GPU, wet-lab access, and paid databases
   are optional. Missing optional capabilities produce a narrower route, not
   fabricated evidence.
6. A missing capability that blocks a required proof, official template, data
   collection, or ethics step must remain a visible blocker.
7. Use a full multi-reviewer ensemble only for `deep`, final submission audit,
   conflicting verdicts, or a concrete integrity risk.
